# SC Board

A player-prop board for the NHL, NFL, NBA and MLB: the slate's Underdog lines next to each player's hit rates, last-10 chart, head-to-head record and the opponent's defense against their position. It builds to static pages you can open from disk or host on GitHub Pages.

## Run it

    pip install -r requirements.txt
    python -m props

That refreshes the game logs, fetches the current Underdog lines, writes `site/index.html` (NHL), `site/nfl.html`, `site/nba.html`, `site/mlb.html`, `site/cfb.html`, `site/soccer.html` and the Underdog lines viewer `site/ud.html` (an app of its own, not in the boards' header), and opens the first. Switch leagues from the header. Click a row (or search any player) to open their page: chart, filters and game log. The browser's Back button returns to the board where you left it.

| Command | What it does |
|---|---|
| `python -m props` | refresh + build + open |
| `python -m props publish [--logs] [--offline] [--upload [--full]]` | refresh everything for the site in one go: the game logs (once a slate day; `--logs` again), every board and the lines page at once, then the upload zips, and with `--upload` send what changed to the host (see Publishing) |
| `python -m props upload [--dry-run] [--clean] [--full]` | send `site/` as it is to the host over FTPS. `--dry-run` connects and lists what would change; `--clean` sends every file and then deletes everything else in the folder (after asking), so it holds exactly `site/` |
| `python -m props refresh [--league nhl]` | update the season in progress |
| `python -m props build [--league nfl] [--offline] [--open]` | fetch Underdog lines, sportsbook prices, schedules and rosters, write `site/`. `--offline` reuses the last fetch, unless it was made on an earlier slate |
| `python -m props lines [--league nhl] [--offline]` | fetch moneylines, totals and spreads for the slate's games and write `site/lines.html`, a game-lines page of its own |
| `python -m props backfill nhl 20242025 20252026` | rebuild whole seasons (under ten seconds each) |
| `python -m props backfill nfl 2024 2025` | same for the NFL |
| `python -m props backfill mlb 2025` | same for MLB (about twenty seconds a season) |
| `python -m props backfill nba 20242025 20252026` | same for the NBA (about forty seconds a season) |
| `python -m props grade [--league nhl]` | grade the books and Fair from the price snapshots against the game logs; writes `data/grades.json` (see Grading). `publish` runs it once a day, after the game logs refresh |
| `python -m props serve [--port 8000]` | serve `site/` so a phone on the same network can open it |
| `python -m unittest discover -s tests -t .` | run the tests |

## What a board shows

- **Every player on the slate**: one row per prop for each player expected to play. Where Underdog has a line, the row uses it and shows the odds. Where it doesn't, the row uses a typical line, the half-point above the player's recent average rounded down, shown in lighter type with no odds. A typical line is left off when it is a foregone conclusion for the player (he lands on one side of it in fewer than 15% of those games), though every stat stays available on his page. "Underdog lines only" hides the typical rows.
- **Line** and **UD**: the line and Underdog's decimal payout for the side you picked (Over or Under). A standard pick pays 1.87x; the "UD standard" filter keeps only those.
- **Pinnacle**, **FanDuel**, **DK** (DraftKings), **Kambi**, **Novig**, **Kalshi**, **Mise** (Mise-o-jeu), **Betano**, **Bovada**, **Fair** and **EV**: each book's decimal price for the same side; the chance of that side with the vig removed, a weighted average of the sharp books posting both sides at the row's line (see **How Fair is weighted** below); and what the site you're betting on pays against that chance: fair × price − 1. The vig comes off each book by scaling both sides' implied chances to add up to 100%. A sharp book's one-way over at the row's line (FanDuel's anytime TD at 7.50x) is the most that book thinks the over's chance can be, so the fair chance never goes above it; the Fair cell says so when it does. That matters most for longshots, where books load more of their margin onto the long side: an anytime TD at +512/−764 scales to 15.6%, but FanDuel's 7.50x caps it at 13.3%. The "EV" toggle picks that site: Underdog's payout, or Mise-o-jeu's, Betano's, Stake's or FanDuel's price at the row's line, each shown as the site's icon (`props/img/`). FanDuel is also a sharp book, so when it's the site picked it is left out of Fair (and of its cap): a book is never measured against itself, and the Pinnacle, DraftKings and FanDuel set can't make Fair then, so Novig or Kalshi must have the row. DK Pick6 is shown for comparison only. Every book's column heading is its icon too (its name on hover and in the sort menu); the chosen site's icon has a blue ring. Mise-o-jeu and Betano are sites to bet on, not sharp prices, so they never count toward the fair chance, even when they post both sides. Kambi is shown but never counts either (below). Bovada is shown for comparison only: its prices are soft and it doesn't take Canadian players, so it neither counts toward the fair chance nor is a site to pick in the "EV" toggle. The best price is green when more than one book has the line. A standard 1.87x pick needs 53.5%, so a coin flip is already −6.5%. Only +EV picks and those worse than −15% are shaded. A book with a different line has its price greyed with its line under it and is left out of the fair chance, except Novig and Kalshi, whose other lines give an estimate (below). Every over/under a book posts for the row is kept, whatever its line: hovering a book's price lists them all, a one-way price (a ladder's rung at Underdog's line) shows the book's nearest over/under under it ("O/U 33.5 1.88x"), and a player's page lists each with a button to move there, where Fair and EV are worked out at that line. The under side reads only prices that have an under, so a book with just a rung at Underdog's line shows its over/under's under, greyed, at its own line. A FanDuel price can be an over with no under (FanDuel's "To Record 2+ Hits" is the over at 1.5): it can't be devigged, so it is never green and only caps the fair chance as above, and the Under side shows nothing for it. A one-way price never makes a Fair on its own: with no sharp book posting both sides at the row's line there is no fair chance or EV, only the books' prices. With no book on Underdog's line there is no fair chance or EV. "+EV only" keeps the picks above zero. A player's page says the same in a sentence, with a button to move to each book's line. Every site's column stays on narrower screens: the hit-rate columns go first, then a player's game moves under his name.
- **How Fair is weighted**: each sharp book with both sides at the row's line has its vig removed on its own, by the power method (the k with a^k + b^k = 1 for the two implied chances, `books.devig`), which takes more of the margin off the longer side the way books load it, and their chances are averaged in log-odds, each by its weight: Novig 7, Kalshi 7, Polymarket 7, Pinnacle 1.4, DraftKings 1.4, FanDuel 1 (`WEIGHT` in each book's module). The weights follow a study of a quarter million graded closing prop prices, where the exchanges' closing numbers held up best. Kambi's weight is 0: its odds also serve BetRivers, which that study found the rest of the market moves away from, so its column is there to compare but never moves Fair. A book whose two sides imply more than 110% (`books.MAX_OVERROUND`) is left out at that row: nobody is making a real price there (Novig often posts that wide hours before a game). Fair counts only when Novig, Kalshi, Polymarket, or all three of Pinnacle, DraftKings and FanDuel are among the books behind it (`books.CONFIDENT`). Otherwise Fair and EV are left blank: the row shows the books' prices only (a player's page says which books had both sides). Hover Fair to see each book's chance and weight.
- **Novig, Kalshi and Polymarket off the row's line** (`books.ESTIMATE`): an exchange with no two-way price at the row's line still counts, estimated from its other lines, and the Fair cell says **est**. Each of its lines is devigged on its own (a Kalshi rung's Yes and No asks are a two-way price). With lines either side of the row's, its chance there is read across between them in log-odds (Kalshi's 60+ and 70+ yards give 62.5). With lines on one side only, its nearest is moved to the row's line by the slope of the player's ladders on the other books (Stake's 36.5, 37.5, 38.5 attempts), or, where no book has a ladder for him, by the median slope of that stat's ladders across the board, scaled to the line. A move is made only within a unit (a tenth of the line, at least 1) and not past 0.75 in log-odds, so a 1.5-goal price never stands in for the anytime goal. An estimate's weight halves for each unit it reaches, and a move counts three quarters of that (Kalshi's 22.5 saves on a 23.5 row: 7 × 0.75 × 0.5^(1/2.35) ≈ 3.9). An estimated exchange still meets the exchange rule. Hover Fair to see how each was made ("Kalshi 45.0% est. moved from 22.5 (weight 3.9)").
- **2+ TDs** (NFL): its own tab, always at 1.5, so it doesn't crowd out the anytime TD row. A player gets a row when any book prices him there: DraftKings' "2+ TDs", FanDuel's "To Score 2+ Touchdowns", Mise-o-jeu's "2+" rung, Kambi, Novig and Bovada likewise. Underdog's own TD lines at 1.5 land here too. Most of these prices are one-way and long, so only Novig's two-way 2+ gives a fair chance and EV; otherwise the row shows each book's price for comparison.
- **Last 10**: one bar per game, oldest to newest, with the line drawn across. Green landed on your side of the line, red did not.
- **L5 / L10 / L20 / season / H2H**: share of games on your side of the line. H2H is every stored game against the next opponent. Samples under three games are shown but not shaded, and sort below real samples. Playoff games are left out of all of these unless you turn on "Include playoffs", on the board or on a player's page; the setting is shared and remembered.
- **DvP**: where the opponent ranks in what it allows to the player's position group per game, measured against each opposing group's own average so a soft schedule doesn't flatter a defense. 1st is the stingiest. Only this season's games count, so the ranks are thin for the first few weeks and a team that hasn't played yet has none.

On a phone the board is laid out as an app rather than a shrunken table: each prop is a card with its chart and every hit rate, games and stats are swipeable chip rows, a bottom tab bar switches between the board, your watchlist and search, and a player's page gets a back button in the top bar. It can be added to the home screen.

A player's page can split his games by teammate. Pick one from the Teammate list and switch between With and Without: every hit rate, the chart and the game log then use only the games that teammate played in, or only the ones he missed. A teammate counts for a game when he played in it for the same team, so one who has since been traded still works, and the games since he left count as without him. An NFL quarterback counts when he took half the snaps, or when he started and left hurt, since the game was planned around him. Add more than one to combine them (without A and without B).

The slate is today's games for the NHL and MLB and the next seven days for the NFL. A slate is never counted in the hit rates until it rolls over, so a game in progress can't show up as a miss. It rolls over at 5 AM Eastern, or earlier once the league's schedule shows every one of the night's games final; a build or refresh after that moves the board to the new day and adds the night's games to the logs.

| | NHL | NFL | NBA | MLB |
|---|---|---|---|---|
| Which games count | every skater game; goalie starts only | any game with an offensive snap; a quarterback needs half the snaps | every game with minutes played: regular season, play-in and playoffs (the play-in counts with the playoffs), never the preseason | a hitter's starts in the lineup; a pitcher's starts on the mound |
| Expected to play | on the roster and in the lineup within the team's last 5 games | played in one of the team's last 2 games | on the roster and in one of the team's last 5 games | in the posted lineup or, before it is out, on the active roster and started one of the team's last 3 games; pitchers: the probable starter only |
| Typical line from | last 20 regular-season games | last 8 regular-season games | last 20 regular-season games | last 20 regular-season games |
| Also shown | B2B tag and rest filter | snap counts | B2B tag and rest filter, minutes | lineup spot, plate appearances, pitch count |

## College football and soccer

The CFB and Soccer boards are odds boards: each book's price, Fair and EV, worked out exactly as on the other boards, but no game logs behind them, so no chart, hit rates, DvP, typical lines or player pages. The search box filters the board by name instead, and the board sorts by EV. Rows are keyed by the player's name, which is also how each book's price finds its row.

- **Every game, not just Underdog's** (`props/market.py`). The game list is every game Kambi lists in each competition over the slate, whether or not Underdog has lines for it; Underdog's games are matched onto them by kickoff and the team names they share most, and one Kambi doesn't list is added from Underdog. The sidebar groups them by day, then by competition, each game by its matchup and kickoff.
- **Rows at the market's line.** Underdog's lines are rows as before. Every other player and stat two books price in a board game gets a row at the market's line: the line most sharp books post both sides at, then the most books post both sides at; with only ladders, the rung most books have that sits nearest even money. "Underdog lines only" hides those. Each book files a prop under its game, which is how a market row knows its game; a book's name spelled out in full ("Pedro Lomba Neto") is the shorter one another book uses in that game ("Pedro Neto").

- **Which books.** College football: Pinnacle (league 880), FanDuel, DraftKings, Kambi, Mise-o-jeu, Betano and Bovada, read with the NFL's stat names (`props/leagues/cfb.py`). Novig and Kalshi post college games but no player props, so a college row has Fair and EV only with all of Pinnacle, DraftKings and FanDuel at the line, and most college rows show none. Soccer (`props/leagues/soccer.py`) covers the Premier League, Champions League, Europa League, La Liga, Serie A, Bundesliga, Ligue 1 and MLS. Each competition lists its place at every book (`COMPETITIONS`), and a book is asked once per competition it carries. Novig has the Premier League and MLS only, Kalshi mostly goalscorers (the Champions League also has assists, shots, shots on target and saves), Pinnacle only a few Yes/No "To Score" markets, and DraftKings' soccer isn't mapped yet. Most soccer props are one-way ladders ("2+ Shots on Target", "Anytime Goalscorer"), so most soccer rows have no Fair or EV until Novig or Kalshi post the two-way price.
- **Only the board's games, and the next two days' for the costly books.** The books asked game by game ask only for games that start within 20 minutes of one on the board and share a word of a team's name with it (`props/matchups.py`). Those that cost a request per game (FanDuel, Novig, Betano, Stake: `PER_GAME`) ask only for games in the next 48 hours (`NEAR_HOURS` in `site.py`) and Underdog's; the others (DraftKings, Kambi, Mise-o-jeu, Bovada, Pinnacle) answer many games a request and are asked for every game. A later game shows only their prices until it comes within two days.
- **Name matching.** With no player ids, a name decides. Two players on the board with the same name and stat get no book prices; a book that tags a player with a team the board knows must agree with it. Bovada sometimes files a player under the wrong club, which can put its (show-only) price on the namesake's row.
- **Not yet.** Game lines for these two leagues: the lines page matches teams by name, and that table has only the four pro leagues so far.

## Where the data comes from

- **NHL game logs**: the NHL stats API (`api.nhle.com/stats/rest`), which returns official per-game numbers for every player in a date range. A day costs five requests however many games were played. Schedule and rosters come from `api-web.nhle.com`.
- **NBA game logs**: ESPN's open site API (`site.api.espn.com`): the scoreboard lists a day's games and each game's summary carries its box score, so a day costs one request plus one per game, six at a time. Rosters come from the same API. The NBA's own stats.nba.com hangs for scripted requests and cdn.nba.com refuses them. Preseason games make the slate, so Underdog's preseason lines show against last season's games, but they never enter the logs: starters play a half. Book coverage was thin in the preseason: Pinnacle, FanDuel and Novig had NBA props, DraftKings, Kambi, Mise-o-jeu and Bovada only game lines, so their NBA maps are empty or unconfirmed and the build lists what they post once the season starts. Mise-o-jeu's NBA tag (`27726`) is its preseason one.
- **MLB game logs**: the MLB Stats API (`statsapi.mlb.com`). It has no bulk game log, so a day costs one schedule request plus one boxscore per game, trimmed to the stored columns. Probable pitchers, posted lineups and active rosters come from the same API. A two-way player (Ohtani) is filed under one position so his page carries both his hitting and his pitching.
- **NFL game logs**: [nflverse](https://github.com/nflverse/nflverse-data) weekly player stats, snap counts and schedule, one file each per season. The stat file has no row for a player who played without recording anything (a receiver with 36 snaps and no targets), so those games are added back as zeros from the snap counts; otherwise hit rates would run high.
- **Lines**: Underdog's `over_under_lines` endpoint, one request per league. `state_config_id` is state-specific; if prices or availability look wrong, copy yours from the request in DevTools and set `UNDERDOG_STATE_CONFIG_ID`.
- **Pinnacle prices**: the guest API Pinnacle's own site uses (`guest.api.arcadia.pinnacle.com`), two requests per league, no key. A prop is matched to a board row by player name and stat; a name two players on the board share is skipped. Each league's `PINNACLE_STATS` maps Pinnacle's stat names to ours, and the build lists any it doesn't recognize. In the NHL preseason Pinnacle posted goals only, so the other NHL names there are unconfirmed. For MLB the prop is named by the words after "Total" ("Total Earned Runs" has units "Runs").
- **FanDuel prices**: the API FanDuel's own site uses (`sbapi.nj.sportsbook.fanduel.com`, set `FANDUEL_STATE` for another state), with the public key its pages send. One request per league plus one per prop tab per game on the slate. Over/under markets give a fair chance: pitcher strikeouts and outs, NFL yardage, receptions and passing TDs, NHL shots and goals. Most other props are one-way ladders, an over with no under: "To Record 2+ Hits" lists every player's price for two or more (the over at 1.5), "Zay Flowers - Alt Receptions" lists one player's price at each rung, and anytime goal and touchdown scorers are the over at 0.5. Those cover MLB batters, NHL points, assists and goals, NFL touchdowns and alternate yardage lines. Where FanDuel has several prices for a row, the row gets the one at its line (over/under first), else an over/under at another line, else the nearest rung. Each league's `FANDUEL_STATS` maps FanDuel's over/under market names to ours and `FANDUEL_LADDERS` the stat in its ladders. It isn't a published API, so it can change without notice; the build then falls back like any other fetch.
- **DraftKings prices**: the API DraftKings' own site uses (`sportsbook-nash.draftkings.com`, state site `dkusny`, set `DRAFTKINGS_SITE` for another). That host refuses a request without the cookies the sportsbook's home page sets, so a fetch opens the home page first and keeps its cookies. Each league lists its prop categories, each category its subcategories by name; only the "... O/U" ones are two-way, and each league's `DRAFTKINGS_STATS` maps those names to ours (MLB batter and pitcher props, NFL passing, rushing, receiving and kicking, NHL shots, points, assists and saves). The rest are one-way "N+" ladders, each rung the over half a point below it (Macklin Celebrini's "3+" shots is the over at 2.5), and `DRAFTKINGS_LADDERS` maps those (NHL shots, points and assists, NFL receiving, rushing and rush + receiving, MLB batter props and pitcher strikeouts). Goals and touchdowns are fields, a runner per player in one market per game, and `DRAFTKINGS_FIELDS` maps those by name with the count as N: the NHL's "Anytime Goalscorer" and "2+ Goals", the NFL's "Anytime TD Scorer", "2+ TDs" and "3+ TDs" from its "TD Scorers" category (a team's D/ST runner is left out). The build lists any two-way subcategory it doesn't map, such as quarter props. Requests go three at a time, about 20 to 35 per league, because DraftKings refuses a burst. Same caveat as FanDuel: unpublished, so it can change or start refusing.
- **Kambi prices**: the open offering API Kambi serves every sportsbook it runs from (`eu.offering-api.kambicdn.com`), no key or cookies. The brand code picks the book: `ubca` (Unibet Canada) by default, which posts the most two-way props; set `KAMBI_BRAND` for another (`rsiusnj` is BetRivers New Jersey). One request lists the league's games, then ten games at a time (`betoffer/event/1,2,3` carries each game's full offers, 2,000 a request, paged with `range_start`). An offer is named by its criterion, and each league's `KAMBI_STATS` maps it to ours with its count written as N ("N+ Receptions By The Player - Including Overtime"). NFL passing, rushing, receiving and kicking come as over/unders and ladders, MLB hitting and pitcher strikeouts and outs likewise, and the NHL's goals, points and assists as yes/no ladders (a ladder's "No" is the under where Kambi posts one). Quarter, half and period offers are skipped quietly; the build lists other player offers it doesn't map (longest plays, defensive stats). Kambi writes some first names in full (Joshua Morrissey), which finds no row.
- **Mise-o-jeu prices**: the content service Loto-Québec's Mise-o-jeu+ site uses (`content.mojp-sgdigital-jel.com`), no key or cookies, just the site's Origin. One request lists the league's games (soccer's competitions all in one, their tags comma-separated), then one per ten games for their markets. A market is named by a group code, and each league's `MISE_STATS` maps those codes to ours. NHL shots, points and assists and most NFL yardage, receptions and attempts come as over/under pairs; the rest, and every MLB prop, are "N+" ladders, each rung the over half a point below it ("3+" is over 2.5). Quarter, half and period markets are skipped quietly; the build lists any other player market it doesn't map (sacks, longest plays). A name Mise spells differently from the game logs (Mitchell for Mitch Marner) finds no row.
- **Novig prices**: the API Novig's own site uses (`api.novig.us/nbx/v1`), no key, cookies or login. Novig is a no-vig exchange, so its prices count as sharp. One request lists the league's games (`/trading/NHL/page`), then one per game on the slate before it starts (`/event-details/<id>/player-props`), three at a time. Each player's line has a strike and two outcomes, the over (Yes, "1+") and the under (No), priced as a chance: what it costs to buy that side (0.375 is 37.5%, a 2.67x price). A side nobody is offering leaves the line one-way. Each league's `NOVIG_STATS` maps Novig's market types ("SHOTS_ON_GOAL") to ours: NHL goals, shots, assists, points, power-play points and saves; NFL passing, rushing, receiving, anytime TDs and kicking; MLB batter and pitcher props. First scorer and longest-play markets are listed as unmapped. Novig's trading fees are only readable when logged in, so its prices are taken as posted. Same caveat as FanDuel: unpublished, so it can change without notice.
- **Kalshi prices**: Kalshi's public market-data API (`api.elections.kalshi.com/trade-api/v2`), no key, cookies or login, and published, unlike the books'. Kalshi is a prediction market, so its prices count as sharp. One request lists the league's games (`/events` on its game series, `KXNHLGAME`, with each game's start and home team), then one per stat series (`/markets?series_ticker=KXNHLGOAL`), two at a time. A game's events share the tail of its ticker across series (`KXNHLGOAL-26OCT14MTLWSH`), which is how a prop finds its game; Kalshi trades games while they're played, so only games that haven't started are read. Every market is one rung, "Tom Wilson: 2+ points", the over at 1.5: its yes is the over and its no the under, each priced as what it costs to buy (0.23 is 23%, a 4.35x price). A market is read only with both sides on offer and no more than 10 cents between bid and ask (`kalshi.MAX_WIDTH`); a rung nobody bids on shows a 98-cent ask that would otherwise read as a price. The player's team comes from the ticker ("WSHTWILSON43"). Each league's `KALSHI_STATS` maps its series to ours: NHL goals, points, assists, saves and first goal (no shots series); NFL passing, rushing and receiving yards, receptions, attempts, completions, interceptions and touchdowns (its 2+ rung fills the 2+ TDs tab); MLB batter and pitcher props; soccer's per competition (goals in every league Kalshi has, plus assists and score-or-assist in the Premier League, and shots, shots on target and saves in the Champions League). The NBA series had no markets up in the preseason, so they are unconfirmed. Each market carries its stat from the competition it was asked under, since soccer's series differ by competition. Kalshi's trading fee isn't taken off, as with Novig. Yardage ladders step by 5 or 10 yards, so a Kalshi yardage price lands on a row's line less often than its counts do.
- **Polymarket prices**: Polymarket's public market data (`gamma-api.polymarket.com`), no key, cookies or login. One request lists its sports and each one's series of games; then one request per hundred of the series' open events, markets nested, two at a time. A game's player props are an event of their own ("Texans vs. Jaguars - Player Props"), with the game's start. Every market is one rung ("C.J. Stroud: Passing Yards O/U 149.5", or "2+ Touchdowns" with no line: the over at 1.5); its first outcome is the over, which costs the best ask, and the under costs one less the best bid. As with Kalshi, a market counts only with both sides on offer within 10 cents (`kalshi.MAX_WIDTH`): most of its prop books hold only a 1-cent bid and a 99-cent ask. Each league's `POLYMARKET_SPORT` and `POLYMARKET_STATS` say where it is and map its market types: NFL yards, receptions, attempts, completions and touchdowns (anytime and 2+), college anytime touchdowns, NBA points, rebounds and assists, MLB batter and pitcher props, and soccer goals, assists, goals + assists, shots, shots on target and saves. It has no NHL player markets. It is weighted as Kalshi is, an exchange, and like Kalshi it is one of the sets that make a fair confident. Its soccer prop books are mostly empty before kickoff; NFL touchdowns are where it prices most.
- **Bovada prices**: the coupon service Bovada's own site uses (`www.bovada.lv/services`), no key or cookies. One request lists the league's games with every market of each (asked with no market filter, the listing carries what each game's page would), one request at a time a second apart, since Bovada answers even three at once with "429 Too Many Requests" (a 429 is retried after a pause). A player's over/under is named "Total Receptions - Alvin Kamara (NOR)", his ladder "Alternate Receptions - Alvin Kamara (NOR)" with a rung per outcome ("3+ Receptions" is over 2.5), and a field ladder "Player to record 2+ Hits" with a runner per player ("a Hit" is 1+). Each league's `BOVADA_STATS` maps the name before the player, or the field name with its count as N, to ours. NHL shots and goalie saves come as over/unders and points, assists, power-play points, goals and blocks as ladders; NFL passing, rushing and receiving as both; MLB total bases, H+R+RBI and pitcher props as over/unders and the other batter props as ladders. Period, half and quarter markets are skipped; the build lists other player markets it doesn't map (longest plays, first scorer).
- **Betano prices**: the APIs Betano's own site reads (`www.betano.ca`), which refuse any client whose TLS handshake isn't a browser's — the site's splash screen answers everything else with 403 — so a fetch goes through `curl_cffi` impersonating Chrome (the one extra package in `requirements.txt`). A league page's HTML embeds its games; one request per game lists its markets, each a table: a stat, a row per player, and the over and under at the row's line, with decimal prices. Goal-scorer tables price the anytime, first and last scorer as columns; the anytime column is the over at 0.5 and so is every "Yes" and "N+" market, each rung the over half a point below its count. Each league's `BETANO_STATS` maps the table titles to ours, `BETANO_FIRST` says which scorer tables carry the first-scorer price, and a title's variants ("Points O/U", "Total Points O/U", "2+ Points") all find one stat. A half's or a quarter's table is never a board stat; the build lists other titles it doesn't map (longest plays, defensive stats, first/last touchdowns). Unpublished, so it can change or start refusing.

## Game lines page

`python -m props lines` builds `site/lines.html`, a page of its own, not linked from the board: the slate's games across the books, each with its moneyline, total and spread in decimal odds, the books' no-vig chance of each side weighted for game lines (Kalshi and FanDuel 1.1, Pinnacle and DraftKings 1, Kambi 0; a pair over 110% left out) (**Fair**), and the **EV vs** column for whichever book you pick in the "Value vs" strip. The page also lists the chosen book's best positive-EV sides in a **Top value** panel. Betano is the featured column and the default in the "Value vs" strip, which offers the sites to bet on, Betano, Mise-o-jeu and Stake, each as its site icon (Underdog posts no game lines). Every column heading shows its book's icon. Every book on the page reads an open endpoint; none needs a login.

The other books are read from the same answers as the board's prices, so a refresh asks each once for both pages: Pinnacle from its league feeds, DraftKings from the league's page (it carries the Game Lines' markets), FanDuel from each game's first prop tab (which carries the moneyline, spread and total; the bare game page adds only quarter markets and, for baseball, props that read as totals at 0), Kambi from its bet offers (every rung carries the same "main" name there, so the page keeps them all and picks the line nearest the game's median), Mise-o-jeu from `MONEY_LINE` and its total rungs, Bovada from its league listing (its Game Lines), and Betano from the Winner, Spread and Points markets its league page embeds for every game. Stake's sport listing carries every game's Winner, Handicap and Total markets, so a league is one request; Stake names the home team first. Betway (shown only) is read from the data its league page is served with, one plain request a league, a second apart: the page fills its prices in from a socket, but every game's start, moneyline, spread and total, with their lines, come with the page (its promotional moneylines, "Money Line - 8Up", are left out). A game leaves the page when it starts, at the build and again in the open page, every 30 seconds. Kalshi's moneyline is the cheaper of buying the team's yes and the other team's no, and its total a rung per line, each kept only when tight, as on the board; it counts toward Fair. Novig posts no game lines its API lets us find, so it isn't here. Books that quote several totals keep the one nearest the median main line of the books that quote only one. A team is matched to the board's codes by its full name, then by the mascot phrase it ends with ("NJ Devils" finds New Jersey), which is unique within a league. The sportsbook's board posts its times in Eastern, and the page groups games by the Eastern date.

## Underdog lines viewer

`site/ud.html`, an app of its own like the game lines page (not linked from the boards), lists every line Underdog has up, in every sport it has them for, whether or not the board tracks the stat or has a price for it: fantasy points, quarter and half props, first TD scorer, longest plays, defensive stats, college football, soccer, tennis, UFC, esports. Pick a sport, then narrow by game, stat or a player's name; sort by any column. Each side shows Underdog's payout: green when it pays more than a standard pick, grey when less, a "Yes" side alone where Underdog offers only that. A struck-through line is the line before one of Underdog's discounts, and "alts" marks a stat Underdog has other lines for. The Payout menu narrows to standard lines (Higher and Lower both offered at the standard pick, line not discounted) or to everything else. A player whose line the NHL, NFL, NBA or MLB board covers is a link to his page there, at that line, with his hit rates; "On the board" keeps only those.

The page fetches a sport's lines straight from Underdog when you pick it (the refresh button fetches again), so it is as fresh as the click, from disk or hosted alike. Without a sport, Underdog's endpoint answers every sport at once, some 35 MB, so the build makes that request to learn which sports have lines up and what Underdog calls them, at most every half hour; the page offers those. A sport that starts after the last build appears once the board is rebuilt.

Not covered for the NFL yet: quarter and half props, longest reception/rush/completion, first and last touchdown scorer, and fantasy points (all of them are in the lines viewer). The weekly stats don't carry them, so the build skips those lines and says how many. The same goes for MLB first-inning props, which need play-by-play, and MLB fantasy points, whose scoring isn't confirmed here. NBA quarter props and fantasy points are skipped likewise.

Game logs live in `data/<league>/boxscores/`: one file per finished season, and one small file per game date for the season in progress, so the daily commit is a few kilobytes. When a new season starts the previous one is folded into a single file automatically.

If Underdog can't be reached, the build keeps the last lines it saved and says so at the top of the board. Each sportsbook falls back the same way; with nothing saved, the board shows without its prices. A copy saved on an earlier slate is never used, even with `--offline`: its lines are for games already played, and a book's old prices would land on today's rows by player and stat. The build fetches it again, and if that fails, it leaves the source out and says which slate the saved copy was from. A build whose Underdog lines are all for an earlier slate prints a warning, and a board opened with no lines from today's slate fetches them from Underdog itself, as the refresh button does.

The refresh button in the header fetches Underdog's lines straight from the browser, so it works on the page opened from disk and on the hosted copy alike. One click refreshes every league: the page you are on updates at once, and the other leagues' pages pick up their new lines when you open them. Lines that haven't moved keep their hit rates; a moved or new line is recomputed from the player's game log file. The refreshed lines are remembered in that browser for the rest of the slate. A line Underdog has taken down disappears until the next build, and game logs themselves only update on a build. So do the sportsbook prices: the books refuse requests from a web page, so the button can't fetch them. A refreshed line keeps the build's prices, and its EV is recomputed against the new payout.

## Publishing

`python -m props publish` refreshes everything at once and zips `site/` for a manual upload. Two zips land at the repo root, each with the site's files at its top level:

- `sc-board-pages.zip`: the pages (every board, the lines page, the Underdog viewer), about 0.5 MB. Between game-log refreshes this is all that changes.
- `sc-board-site.zip`: the whole site, the 3,700 player files too, about 11 MB.

The run ends by saying which to upload: it remembers the player files of the last full zip it pointed to, so it says `sc-board-site.zip` the first time each day (the game logs moved) and `sc-board-pages.zip` after that. The player files are rewritten only when the game logs, the players listed or the code change.

A refresh is quick because the sources are asked at once and each question once (`props/net.py`). Every league and both pages build at the same time on one clock; a request the props and the lines page share (Pinnacle's feeds, the books' league pages, Bovada's listing, FanDuel's game pages, Kambi's and Mise-o-jeu's games, each asked for once however the two pages batch them) is made once a run; each site keeps its own cap on requests in flight (Bovada one at a time, a second apart; DraftKings three) however many leagues are asking; an answer a site's CDN says stays fresh (Pinnacle 15 minutes, Bovada 10) is kept on disk that long and reused by the next run; and the books asked game by game (Betano, Novig, FanDuel's prop tabs) are asked only for the games on the board, those on the schedule's slate at once and any later game Underdog has lines for once they're read. A run prints how many requests it made to each site. Kambi answers ten games at a time (2,000 offers a request) and Mise-o-jeu ten a request, and Bovada's listing carries every game, so neither is asked for a game's own page.

Each publish (not `--offline`, whose prices aren't new) also keeps the boards' prices for grading, in `data/<league>/snapshots/` (`props/snapshots.py`): every book's price on every row with a player id, and Underdog's payout as the book `underdog`, stored as implied chances in hundredths of a percent with the vig in, so Fair can be worked out again later with any weights. A publish writes only what changed since the last: a price that is new or moved, or a takedown (a record with no line) when a book that was fetched no longer has a price on a game still to come. A book whose fetch failed writes nothing; `publishes.parquet` logs, for every publish, which books were fetched. The price at any moment is the last record at or before it (`snapshots.as_of`): a price's first record is the first publish that saw it (not the book's true open), its last before the start the close. Results aren't stored; they are the box scores. One file per game date, as with the box scores, folded into one file per season at the next season; a first publish of a full NFL week is about 40 KB, a publish where nothing moved adds nothing.

The boards and the lines page drop a game when it starts, both at the build and in the open page (every 30 seconds), so a page uploaded before the slate stays correct through it.

**Publishing automatically.** `python -m props publish --upload` does all of the above and then sends what changed to the whc.ca account over FTPS (`props/upload.py`): only new or changed files, player files first and pages last, each written under a temporary name and renamed into place so a visitor never gets half a page; files `site/` no longer has are deleted. Put `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` and optionally `FTP_DIR` (default `public_html`) in `.env`, which is never committed. `--full` sends every file again. `python -m props upload --clean` sends every file and then deletes everything else in the folder, asking first, so the folder holds exactly `site/`: like emptying it first, but the old site stays up until the new one is in place. It never deletes `.well-known` (the host's certificate checks), `cgi-bin` or `.ftpquota`, nor any top-level names listed in `FTP_KEEP` (comma-separated). A run where more than half the book fetches failed uploads nothing (that is a VPN or the network, not the books), so the site keeps its last good boards. Every build also writes `site/.htaccess`, which has the host send the pages compressed and never serve a stale copy.

`scripts/autopublish.sh install` runs it on this Mac on a schedule (launchd): 5:07 AM for last night's results, then hourly at :07 from 11:07 AM to 1:07 AM, local time. A run missed while the Mac sleeps happens when it wakes. `status` shows whether it's on and the end of its log (`~/Library/Logs/sc-board-publish.log`), `uninstall` turns it off. It runs here rather than on GitHub because the books refuse cloud servers the way they refuse a VPN, and the host's rules don't allow building the site there. `.github/workflows/tests.yml` only runs the tests on each push.

## Grading

`python -m props grade` (`props/grade.py`) checks the prices the snapshots kept against what happened, with no requests. For each league with game logs it writes to `data/grades.json`:

- **books**: each book's devigged closing price (its last before the game) against the result at its line, as log loss and Brier score, and, on the same props, how much better or worse it did than Fair made from the other sharp books alone (`vs_rest`). A book with a positive gain knows something the rest don't; that is the number to set `WEIGHT` by.
- **fair**: Fair at close, its log loss and its calibration (props bucketed by Fair's chance of the over, against how often the over landed), for every prop and for the confident ones.
- **targets**: every side each betting site offered that the board showed as +EV, graded from the first publish that showed it: the EV shown, its closing line value against Fair at close, how often it won, and the return per unit at that price.

Fair is worked out as on the board (power devig, log-odds by weight), at the line only: the board's estimates from an exchange's other lines and its one-way cap are not repeated. A player who didn't play, or a result on the line, is left out. The grades aren't shown on the site: a few days of games is too few to say much, and closing line value settles first.

## Layout

    props/leagues/nhl.py    NHL data and everything hockey-specific (stats, positions, who counts as active)
    props/leagues/nfl.py    the same for the NFL
    props/leagues/nba.py    the same for the NBA
    props/leagues/mlb.py    the same for MLB
    props/leagues/cfb.py    college football: an odds board, no game logs
    props/leagues/soccer.py soccer: the same, over several competitions
    props/matchups.py       which of a book's games are on an odds board
    props/store.py          parquet layout under data/<league>/boxscores
    props/underdog.py       fetch and parse lines, match players to league ids
    props/books.py          the sportsbooks (pinnacle.py, fanduel.py, draftkings.py, kambi.py, novig.py, kalshi.py, polymarket.py, mise.py, betano.py, bovada.py) and matching their props to board rows
    props/metrics.py        hit rates, typical lines, rest days, teammates, defense vs position
    props/site.py           assemble a board, write site/
    props/template.html     the page (inline CSS and JS, no dependencies)
    props/ud.html           the Underdog lines viewer, which fetches its lines in the browser

Adding a league means adding a module to `props/leagues/` with the surface described in `props/leagues/__init__.py`.
